# 06 · V2 大版本：多 AI 编辑器 + 手机桥接

> 版本：PC 端中间件 **v2.0.0** ｜ 固件 v1.5.0（灯效可配置版）｜ 协议 `ai-status/1` + `ai-status-phone/1`
>
> 一句话：从「只服务 CodeBuddy 的一盏灯」升级为「一套硬件 + 三套 AI 编辑器 + 手机端」的统一状态面板。

---

## 一、V2 新增了什么

| 能力 | V1（v1.3.x / v1.4.0） | V2（v2.0.0） |
| --- | --- | --- |
| AI 编辑器 | 仅 CodeBuddy | **CodeBuddy / OpenAI Codex / DeepSeek (DSH)**，映射外置到 `profiles/` |
| 手机查看 | 需单独启动 `pc-bridge` | **随 `start.bat` 一体化启动**，UDP 发现 + 固定配对码 |
| 端口 | 手动 | `start.bat` **自动放行** TCP 8770 / UDP 4211（首次一次 UAC） |
| 远控 V2 | 默认关闭、需手动开 | **默认开启**（手机端仍需打开开关） |
| 启动 | 一个中间件进程 | 中间件 + 手机桥接子进程（联动启停、崩溃自拉起、单实例保护） |
| 稳定性 | 可能多实例抢端口 | 8765/8770 均单实例；`/health` 无锁秒回；断连静默；流式事件节流 |

### 1. 三套 harness 统一映射

映射规则不再写死在代码里，而是 `profiles/*.json`：

| profile | 事件来源 | 关键点 |
| --- | --- | --- |
| `codebuddy.json` | `settings.json` Hooks | 与旧版完全兼容，幂等不重复注册 |
| `codex.json` | `~/.codex/hooks.json` | Codex 原生 `PermissionRequest`，确认框能亮橙灯 |
| `dsh.json` | DSH 插件 `ctx.on` | 31 个真实事件；`approval/request` 审批、`assistant/message` 输出、`session/event(type=turn/end)` 完成 |

状态闭环（避免「写代码一闪而过」「完成了不结束」）：

- 工具跑完**保持** `coding` / `searching`，直到下一个工具或本轮结束；
- `approval/decided` 放行/拒绝后**立即**解除橙闪；
- `turn/end` → `done` → 10s → `idle`；`session/close` → `idle`；
- 启动期生命周期事件（`agent/created`、`session/agent-busy`）不再误报思考。

### 2. 手机桥接（HarmonyOS / 微信小程序）

- 手机访问：`http://<电脑局域网IP>:8770`（TCP）
- 局域网发现：UDP **4211** 广播，手机发 `{"t":"discover","proto":"ai-status-phone/1"}`
- 默认配对码：**`123456`**（固定在 `config.json` 的 `phone_bridge_pin`）
- 远控 V2（键鼠注入）：默认开启，**两端都要打开**才生效

### 3. 一键启动

双击 `start.bat` 依次完成：

1. 检查防火墙规则，缺失且非管理员时自动 UAC 提权放行 TCP 8770 / UDP 4211（规则建好后不再弹）；
2. 启动中间件（8765）；
3. 自动拉起 `tools/pc-bridge/bridge.py`（8770 / 4211）；
4. 服务退出时桥接一起停止；桥接崩溃自动重启。

## 二、关联项目

手机端可以直接使用以下两个开源项目连接本机桥接：

| 项目 | 地址 | 说明 |
| --- | --- | --- |
| **微信小程序** | <https://gitee.com/chenjimo/we-chat-mini-demo> | 小程序端：局域网搜索 / 配对 / 状态展示 |
| **鸿蒙 App（harmony-bridge）** | <https://gitee.com/chenjimo/harmony-bridge> | HarmonyOS 端：状态查看 + 远控 V2 |

使用前提：

1. 电脑已启动本项目的 `start.bat`（中间件 + 手机桥接）；
2. 手机与电脑在**同一局域网**（不要跨网段/VPN）；
3. 手机端搜索到电脑后，输入配对码 `123456`；
4. 用远控时，手机端打开「允许远控」，电脑端 `phone_bridge_enable_input` 为 `true`（默认）。

> 协议为 `ai-status-phone/1`（明文 HTTP/WS）。仅限可信局域网，**不要做公网端口映射**。

## 三、快速开始（5 分钟）

### 1. 电脑端

```bat
:: 双击即可；也可以命令行
start.bat
```

看到类似输出即成功：

```
手机桥接  http://192.168.1.4:8770   UDP 发现 :4211   PIN 123456
```

检查：

```bat
python main.py phone-bridge status
:: phone_url / pin_in_use / http_listening
```

### 2. 手机端

1. 安装/打开微信小程序或鸿蒙 App；
2. 让它搜索局域网设备（UDP 4211）；
3. 选中你的电脑 → 输入 `123456`；
4. 进入状态页，即可看到 思考 / 找资料 / 编写 / 输出 / 需确认 / 完成 / 失败。

### 3. AI 编辑器接入

```bat
:: CodeBuddy（IDE / CLI）
python main.py install-hooks --write --harness codebuddy

:: OpenAI Codex
python main.py install-hooks --write --harness codex

:: DeepSeek (DSH)：生成插件后按提示安装
python main.py install-hooks --write --harness dsh
dsh plugin --profile desktop ...   :: 实际以 DSH 版本提示为准
```

> DeepSeek 桌面版的 `desktop` profile 由 Electron 独占管理，插件通过 `cordis.patch.yml` 的
> `- insert:` 块（相对路径 `./node_modules/aistatus-led-dsh/index.mjs`）加载；
> 详见 `tools/dsh-plugin/README.md`。装好后重启 DSH，`/events` 出现
> `aistatus/plugin-loaded` 即代表加载成功。

## 四、配置速查（`config.json`）

```json
{
  "listen_port": 8765,
  "phone_bridge_enabled": true,
  "phone_bridge_port": 8770,
  "phone_bridge_discovery_port": 4211,
  "phone_bridge_pin": "123456",
  "phone_bridge_pair_required": true,
  "phone_bridge_enable_input": true,
  "phone_bridge_firewall": true,
  "done_hold_ms": 10000,
  "error_hold_ms": 3000
}
```

常用命令：

```bat
python main.py start                      :: 启动（含手机桥接）
python main.py phone-bridge status        :: 手机桥接状态/地址/实际配对码
python main.py phone-bridge pin 888888    :: 改配对码（6 位，重启生效）
python main.py phone-bridge firewall      :: 手动放行端口（需管理员）
python main.py selftest                   :: 107 项自检
python main.py demo                       :: 真机灯效演示
```

关闭某一项：

- 只要灯、不要手机：`"phone_bridge_enabled": false`
- 只要状态、不要远控：`"phone_bridge_enable_input": false`

## 五、故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 手机搜不到电脑 | 防火墙未放行 / 不同网段 / 桥接未启动 | 管理员跑 `tools\open-ports-admin.bat`；`phone-bridge status` 看 `http_listening` |
| 配对提示 `bad_pin` | 配对码不对 | `phone-bridge status` 看 `pin_in_use`，或 `pin 123456` 重置 |
| `8770` 两个实例 | 手动跑了旧的 `bridge.py` | 关掉旧的；V2 已加单实例保护 |
| `/health` 超时 | 旧版设备发现在锁内 | 升级 v2.0.0；已移出锁 |
| DSH 无事件 | 插件没加载 | 看 `/events` 是否有 `aistatus/plugin-loaded`；检查 `cordis.patch.yml` 的 `insert` 块 |
| 远控注入无效 | 目标是管理员窗口（UIPI） | 以管理员身份运行 `start.bat` |
| 红灯一直亮 | 旧版 error 不消退 | 升级 v2.0.0，红闪 3s 自动消退 |

## 六、升级与回退

- 升级：覆盖 `main.py` / `ai_status/` / `profiles/` / `tools/`，保留自己的 `config.json`，重启服务；
- 回退：使用 `packages/aistatus-led-pc-v1.4.0.zip`（或更早的 v1.3.1），覆盖后重启；
- 建议升级前备份 `config.json` 与 `tools/pc-bridge/phones.json`（已配对设备列表）。
