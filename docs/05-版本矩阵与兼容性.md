## 三、兼容性承诺

| 组合 | 是否可用 | 说明 |
| --- | --- | --- |
| PC v2.0.0 + 固件 v1.5.0（灯效可配置版） | ✅ 推荐 | 三 harness + 手机桥接；闭环完整、零误报；灯效可配；来源绑定 + mDNS |
| PC v2.0.0 + 固件 v1.4.x | ✅ | 状态与完成态在 PC 端完成；无来源绑定、无 `/api/fx` |
| PC v1.4.0 + 任意固件 | ✅ | 可用（三 harness，无手机桥接），建议升级 v2.0.0 |
| PC v1.2.0 + 任意固件 | ⚠️ 不推荐 | 功能可用，但会把深度思考误报成 `need_input` / `need_confirm` |
| PC v1.1.0 + 固件 v1.5.0 | ✅ | 完整支持来源绑定、mDNS；但不会主动上报 `need_confirm` / `need_input` |
| PC v1.1.0 + 固件 v1.4.x | ✅ | `src` 被固件按未知字段忽略；`msg` 里的 `[ID]` 仍会被广播；无绑定功能 |
| PC v1.0.0 + 固件 v1.5.0 | ✅ | 不带 `src`，被视为匿名来源 `*`，功能正常但无法按电脑区分 |
| PC v1.0.0 + 固件 v1.4.x | ✅ | 原始组合 |
| 任意 PC + 固件 v1.3 | ❌ | v1.3 没有状态灯引擎与 `/api/status` |

保证事项：

- 新增字段一律**并列添加**，不修改/删除已有字段语义。
- 不带 `src` / `seq` / `reqId` 的旧客户端行为与旧版完全一致。
- v1.4.x 全部接口、命令、字段在 v1.5.0 中保持不变。
- 状态引擎关闭时，LED 行为与 v1.3 一致。

## 四、升级路径

| 从 | 到 | 操作 | 是否要重装 Hooks |
| --- | --- | --- | --- |
| PC v1.0.0 ~ v1.4.0 | v2.0.0 | 覆盖 `main.py` + `ai_status/` + `profiles/` + `tools/`，**重启服务**；`start.bat` 会自动拉起手机桥接 | **是**（若装 Codex / DSH） |
| 从 v1.2.0 升级 | v2.0.0 | 旧 `config.json` 的 `infer_need_*` / `need_*_after_ms` 已废弃，留着会被忽略 | 否 |
| 想用手机端 | v2.0.0 | 默认已集成；`phone_bridge_*` 可调端口 / 密钥 / 远控 | 否 |
| 任意 PC 换了目录/端口 | — | 重跑 `install-hooks --write` | **是** |
| 想兜底「长时间无响应」报红 | — | `config.json` 设 `stalled_after_ms: 300000`（默认 0 关闭） | 否 |
| 固件 v1.4.x / 旧 v1.5.0 | v1.5.0 灯效可配置版 | 重新编译烧录 `ESP-S3-Demo1.ino`（先改 WiFi 占位符） | 否 |
| 换电脑 | — | 走 `docs/01` 第 2 节全流程 | **是** |
| 换 ESP32 板 | — | 烧录 + 改 `arp_mac_prefix` + 网页重新勾选来源 | 否 |

## 五、联调前核对清单

```
□ 设备 GET /api/hello 的 fw 与本表一致
□ 设备 GET /api/hello 的 proto == "ai-status/1"
□ 串口 {"t":"ping","v":1} 回 pong
□ PC /health 的 version == 1.3.1
□ PC /health 的 source_id 与 identity 输出一致
□ python main.py selftest → 107 项通过
□ 故意读一个不存在的文件 → /events 里该条 state == error，设备红闪约 3s 后恢复
□ 设 need_confirm 后随便调一个工具 → 立即变回工作态（sticky 清空）
□ 发一句需求后停下来 1 分钟，/health 的 state.waiting_for_human == false（不误报等待态）
□ Stop 后完成态持续 10s，done 帧 ttl == 10000
□ 设备网页「来源与绑定」里能看到该 source_id
□ 若 mode=1，确认该 source_id 已勾选（否则 source_not_bound）
□ PC 与设备在同一网段（或已用串口直连）
```

## 六、限制

- 设备只有 1 颗 WS2812，多来源只能聚合显示一个状态。
- 设备不做状态历史；统计需 PC 端自行落库。
- 跨网段发现不可行（广播/mDNS/扫描都过不了路由器）。
- 无鉴权、无 TLS、开放 CORS，仅限可信局域网。
- PC 端串口实现为 Windows 专用；Mac/Linux 需 `pyserial` + 调整串口枚举，或设 `prefer_serial: false` 走局域网。
- PC v1.3.0 起不做静默推断：IDE 实测不发确认 / 提问事件，`need_input` / `need_confirm` 在 IDE 下基本不会自动亮；需要时显式上报 `ai_status_state` 或 `POST /state`。
- 颜色与动效由固件 `STATUS_DEFS` 决定，只改 PC 端无法把「黄色慢闪」改成「黄色呼吸」、把「绿色常亮」改成「绿色慢闪」；PC 端能改的只有状态判定与 `ttl` 时长。
