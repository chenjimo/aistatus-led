# 01 · 换环境从零部署（最重要的一篇）

适用：换了一台电脑、刚从 Gitee 下载下来、换了 WiFi / 网段、换了一块 ESP32、想改端口或来源 ID。

---

## 0. 先搞清楚三层分别装在哪

```
┌─ ① CodeBuddy Hooks ────────────────────────────────┐
│  位置：每台电脑自己的 ~/.codebuddy/settings.json     │
│  作用：AI 每次提交需求 / 调工具 / 结束回复时，       │
│        启动一个短命进程，把事件 POST 给本机 8765     │
│  ★ 每台电脑必须单独安装，且命令里含本机绝对路径     │
└───────────────────────┬────────────────────────────┘
                        ▼
┌─ ② PC 端中间件（本仓库 main.py + ai_status/）──────┐
│  位置：任意目录，常驻运行（start.bat）              │
│  作用：状态机仲裁 → 串口 / HTTP 发给 ESP32           │
│  ★ 文件可复制；配置 config.json 按环境修改          │
└───────────────────────┬────────────────────────────┘
                        ▼
┌─ ③ ESP32-S3 固件（esp32/firmware/*.ino）───────────┐
│  位置：烧进板子，与 PC 无关                         │
│  作用：按状态点灯、按 src 绑定来源、提供 Web 面板    │
│  ★ 换网络时要改源码里的 WiFi 占位符再重新烧录       │
└────────────────────────────────────────────────────┘
```

**最常见的两个坑**：以为复制了目录 Hooks 就跟着过去了（不会）；以为 `client_id.json` 要一起复制（千万不要，两台电脑会变成同一个 ID）。

---

## 1. 获取代码的三种方式

| 方式 | 命令 / 位置 | 适合 | 之后要做 |
| --- | --- | --- | --- |
| A. 克隆仓库（推荐） | `git clone https://gitee.com/chenjimo/aistatus-led.git` | 想保留文档、以后 `git pull` 升级 | 走第 2 节 |
| B. 下载仓库压缩包 | Gitee 页面「克隆/下载 → 下载 ZIP」 | 不装 Git | 解压后走第 2 节 |
| C. 只下发布包 | `packages/aistatus-led-pc-v1.2.0.zip`、`packages/aistatus-led-esp32-v1.5.0.zip` | 只要能跑的文件 | 解压后走第 2 节；文档需另看仓库 `docs/` |

发布包 PC 端内容（18 个文件：源码 + 全部 5 篇文档）：

```
main.py
ai_status/           7 个 .py（协议 / 映射 / 状态机 / 串口 / 设备 / 服务）
config.example.json  requirements.txt  start.bat
README.md            CHANGELOG.md
docs/01 ~ docs/05    全部 5 篇
```

包里不含 `config.json`、`client_id.json`、日志、Hooks 生成片段等本机运行物，解压后是一个干净的可运行环境。

> `main.py` 放在解压目录根部即可，**位置可以任意**，但一旦装好 Hooks 就别再挪目录；挪了要重跑 `install-hooks --write`。

## 2. 新电脑部署 PC 端（逐步照做）

### 步骤 0 · 环境

| 要求 | 检查 | 不满足会怎样 |
| --- | --- | --- |
| Python 3.10+ 且在 PATH | `python --version` | `start.bat` 提示找不到 python；Hooks 也起不来 |
| Windows（串口直连） | — | Mac/Linux 见 4.8 |
| CodeBuddy（IDE 或 CLI） | — | 无 Hooks 就没有事件 |

`requirements.txt` 里的 `pyserial` 是**可选**增强（更标准的串口枚举），不装也能跑：Windows 下自动走内置 Win32 串口实现。

```powershell
python -m pip install -r requirements.txt   # 可选
```

### 步骤 1 · 放置文件

把代码解压/克隆到任意目录（下文用 `<APP>` 表示），例如 `D:\Tools\aistatus-led`。

```powershell
cd <APP>
python main.py selftest
```

**期望**：`自检完成：67 项全部通过`（含「需要人处理」推断 / 锁定 / 解除的端到端验证）。这一步不需要硬件，先证明代码在自己电脑上能跑。

### 步骤 2 · 生成这台电脑的来源 ID

```powershell
python main.py identity
```

会输出 `source_id`（例如 `MyPC-3F9A2B`）并生成 `client_id.json`。**把这个 ID 记下来**，后面在 ESP32 网页绑定白名单要用。

- 这个文件首次运行自动生成、之后保持不变（PC 重启不会换 ID）。
- 想自定义：在 `config.json` 里写 `"source_id": "JIMO-PC2"`，重启服务生效。
- **不要从别的电脑复制 `client_id.json`**。

### 步骤 3 · 安装 Hooks（每台电脑必做一次）

```powershell
python main.py install-hooks --write --scope user
```

它会：

1. 用本机的 `sys.executable` 和 `<APP>` 的绝对路径生成 `hooks.settings.ide.json`；
2. 合并进 `~/.codebuddy/settings.json`（用户级，对该电脑所有项目生效）；
3. 自动备份原配置为 `settings.json.bak-<时间戳>`；
4. 重复执行是幂等的，不会插入重复命令。

检查：

```powershell
python main.py hooks-config    # 打印生成的命令，确认路径指向本机的 <APP>\main.py
```

> v1.2.0 起 `Notification` / `PermissionRequest` / `PermissionDenied` / `PostToolUseFailure` / `Elicitation` 已并入默认安装片段，IDE 不发时无副作用。CLI 用户想补齐 `StopFailure` / `SubagentStop` / `ElicitationResult` 等再加 `--with-cli`；装项目级用 `--scope project`（写到 `<工作区>/.codebuddy/settings.json`）。

### 步骤 4 · 重启会话

**Hooks 是会话启动时加载快照，不会热加载**。必须重启或新建一个 CodeBuddy 会话；CLI 用户还需在 `/hooks` 面板审核。不重启的话服务能跑，但一条事件都收不到（`GET /health` 的 `event_count` 恒为 0）。

### 步骤 5 · 按环境改配置（见第 3 节）

```powershell
copy config.example.json config.json
notepad config.json
```

只有需要改的键才写，其余用默认值。

### 步骤 6 · 启动服务

```powershell
start.bat
```

或 `python main.py start`。窗口保持打开。日志同时写到 `ai_status.log`。

### 步骤 7 · 验收

```powershell
python main.py probe                  # 应看到串口命中或局域网 /api/hello
python main.py demo                   # 灯依次变紫→黄→青→绿等
python main.py emit need_confirm      # 橙色快闪并保持
python main.py clear                  # 解除
```

再给 AI 发一句需求，观察灯与 `GET http://127.0.0.1:8765/health` 的 `event_count` 是否增长。

## 3. 必改配置清单

### 3.1 `config.json`（不写则用内置默认值）

| 键 | 默认值 | 什么时候**必须改** | 改成什么 |
| --- | --- | --- | --- |
| `cached_ip` | `192.168.1.13` | 设备换了 IP / 换了网络 | 设备实际 IP，或留空靠 mDNS 与扫描 |
| `mdns_host` | `esp32s3-ai.local` | 改过固件里的 mDNS 名字 | 新域名；不需要则填 `""` |
| `arp_mac_prefix` | `8c-fd-49` | 换了另一块 ESP32 板 | 新板 MAC 前三字节（小写、连字符） |
| `subnet` | `""`（自动取本机 /24） | 设备与 PC 不在同一 /24，或想限定扫描范围 | 例如 `"192.168.43"` |
| `prefer_serial` | `true` | 不接 USB、只走网络 | `false` |
| `lan_scan` | `true` | 已知设备 IP、不想扫网段 | `false`（加快连接） |
| `source_id` | 空（自动生成） | 想用固定好记的 ID / 多窗口区分 | 例如 `"JIMO-PC"`、`"JIMO-PC#win1"` |
| `source_field` | `src` | 固件侧改了来源字段名 | 新字段名 |
| `tag_source_in_msg` | `true` | 不想在 `msg` 里带 `[ID]` | `false` |
| `listen_port` | `8765` | 端口被占用 | 新端口；**同时重跑 `install-hooks --write`** 与所有 `--port` 命令 |
| `heartbeat_ms` | `5000` | 一般不动 | 必须 < 设备 15s 超时 |
| `infer_outputting` | `true` | 不想用启发式推断「输出中」 | `false` |
| `outputting_after_ms` | `1200` | 想让「输出中」更早/更晚出现 | 毫秒，需小于 `need_input_after_ms` 才有两段式效果 |
| `infer_need_confirm` | `true` | 不想推断等待确认 | `false` |
| `need_confirm_after_ms` | `4000` | 命令经常执行超过 4s 被误判 | `8000`~`15000` |
| `infer_need_input` | `true` | 不想让灯一直停在「等待回复」 | `false`（恢复 `done` 5s 回 `idle`） |
| `need_input_after_ms` | `2500` | 想让 `done` 绿灯留更久 | 调大，例如 `5000` |
| `lock_human` | `true` | 调试时允许其它状态覆盖等待态 | `false`（不建议） |

> `listen_port` 改动影响面最大：Hooks 命令里写死了 `--port`，`emit` / `clear` / `hook` 也要带同样的 `--port`。

### 3.2 ESP32 固件源码（换网络必改）

`esp32/firmware/ESP-S3-Demo1.ino` 顶部：

```cpp
#define WIFI_DEFAULT_SSID   "YOUR_WIFI_SSID"        // ← 改成你的 2.4GHz WiFi
#define WIFI_DEFAULT_PASS   "YOUR_WIFI_PASSWORD"    // ← 改成你的密码
#define WIFI_BACKUP_SSID    "YOUR_BACKUP_SSID"      // ← 备用网络，可留空
#define WIFI_BACKUP_PASS    "YOUR_BACKUP_PASSWORD"
#define AP_SSID             "ESP32S3-Fallback"
#define AP_PASSWORD         "YOUR_AP_PASSWORD"      // ← 至少 8 位
```

改完重新编译烧录。**不要把填了真实密码的源码提交到公开仓库。**

设备也支持网页里保存自定义 WiFi（写 NVS，优先级最高），可避免把密码写进源码。

### 3.3 绝对不要手改 / 不要复制的

| 文件 | 说明 |
| --- | --- |
| `hooks.settings.*.json` | 由 `install-hooks` 自动生成，含本机绝对路径 |
| `client_id.json` | 运行时生成；跨电脑复制会导致来源 ID 冲突 |
| `last_ip.json` | 本机缓存的设备 IP，换环境会误导发现 |
| `ai_status.log`、`__pycache__/` | 日志与字节码 |
| `config.json` | 含本机个性化配置，不要跨电脑直接复制；用 `config.example.json` 重新配 |

以上均已加入 `.gitignore`，不会上传到仓库。

## 4. 典型换环境场景：照着改

### 4.1 换了 WiFi / 设备 IP 变了

1. 固件：改 `WIFI_DEFAULT_*` → 重新烧录（或用设备网页保存新 WiFi 到 NVS）。
2. PC 端：优先什么都不改 —— v1.5.0 固件注册了 mDNS `esp32s3-ai.local`，`find_lan()` 会先试缓存 IP，再试 mDNS、ARP 反查、/24 扫描。
3. 若仍找不到：把 `config.json` 的 `cached_ip` 改成新 IP，或 `subnet` 改成设备所在网段。
4. 设备 `GET /api/hello` 能通即说明网络 OK。

### 4.2 PC 与设备不在同一网段

广播、mDNS、`/24` 扫描都过不了路由器。表现：HTTP 全部超时、网页打不开。

- 首选：让 PC 与设备连**同一个路由器/网段**；
- 或者：PC 连接设备 AP（`ESP32S3-Fallback` / 你设置的 `AP_PASSWORD`），设备固定 `192.168.4.1`；
- 或者：**插 USB 线走串口直连**（最省事，不依赖网络），串口 `pong` 里还会带回设备当前 IP。

### 4.3 换了一块 ESP32 板

1. 改 `config.json` 的 `arp_mac_prefix` 为新板 MAC 前三字节；
2. 烧录同一份 `ESP-S3-Demo1.ino`（WiFi 占位符按新环境填）；
3. `python main.py probe` 确认新板 `pong` 的 `fw` 与 `proto`；
4. ESP32 网页「来源与绑定」重新勾选本机 `src`（绑定配置在板子 NVS 里，换板会丢）。

### 4.4 换电脑 / 多台电脑同时用

- 每台电脑：走一遍第 2 节（**Hooks 各自装**），各自 `identity` 得到不同 ID。
- 不要复制 `client_id.json`；`config.json` 里若写了固定 `source_id`，各台要设成不同值。
- ESP32 网页「来源与绑定」里勾选想看的电脑；`仅绑定来源` 模式下未勾选的电脑状态帧会返回 `source_not_bound`，PC 日志会提示「本机未被 ESP32 绑定」。
- 同一台电脑多个窗口想分开：给每个进程配不同 `source_id`（如 `PC-A#win1`），或不同 `--port` 各跑一份服务。

### 4.5 端口 8765 被占用

1. `config.json` 写 `"listen_port": 8877`；
2. **重跑** `python main.py install-hooks --write --scope user`（重新生成带新端口的 Hooks 命令）；
3. 所有手工命令带 `--port 8877`；
4. 注意别的电脑上如果也改了端口，各自保持一致即可（各机回环地址互不影响）。

### 4.6 只想用局域网、不接 USB

`config.json` 设 `"prefer_serial": false`。会跳过串口枚举，直接走 mDNS / 缓存 IP / ARP / 扫描 / AP 兜底。

### 4.7 想关掉 / 调整启发式推断

- 只关「输出中」：`"infer_outputting": false`。该功能靠「工具结束后 1.2s 无活动」推断；关掉后 `outputting` 只能靠 Hook 载荷里的 `ai_status_state` 精确上报。
- 只关「等待回复」：`"infer_need_input": false`，`done` 恢复 5s 回 `idle`。
- 只关「等待确认」：`"infer_need_confirm": false`。
- 两个 `infer_need_*` 都设 `false` 时行为等同 v1.1.0：只有显式上报 / 补强 Hooks 事件能触发 `need_confirm` / `need_input`。
- 长时间运行的命令被误判为等待确认：把 `need_confirm_after_ms` 调到 `8000`~`15000`；工具恢复执行后会自动解除。
- 等待态一直不解除：IDE 可能既没发 `UserPromptSubmit` 也没发 `PostToolUse`，用 `python main.py clear` 手动释放。

原理、解除条件与排错见 `docs/02` 第七节。

### 4.8 Mac / Linux

当前串口直连是 Windows 实现（Win32 API + PowerShell 枚举 + `arp -a` 格式）。

- 安装 `pyserial`：`pip install pyserial`
- 设 `"prefer_serial": false` 走局域网（推荐），或保留 `true` 让 pyserial 枚举串口；
- `arp` 前缀反查在非 Windows 上可能失效，但会自动回落到 /24 扫描；
- 若 `python` 命令是 `python3`，把 `start.bat` 换成自己的启动命令，并确认 `install-hooks` 生成的解释器路径正确。

## 5. ESP32 端从零烧录

| 步骤 | 操作 | 检查点 |
| --- | --- | --- |
| 1 | 安装 Arduino IDE / arduino-cli + ESP32 Core 3.2.1 | 板型可选 ESP32S3 Dev Module |
| 2 | 把 `esp32/firmware/ESP-S3-Demo1.ino` 放进**同名目录** `ESP-S3-Demo1/ESP-S3-Demo1.ino`（Arduino 要求目录名 = 主文件名） | 否则报 `Can't open sketch` |
| 3 | 改顶部 `WIFI_*` / `AP_PASSWORD` 占位符 | 只支持 2.4GHz |
| 4 | 选择 Flash 8MB / PSRAM 启用 / USB CDC On Boot | FQBN 参考 `esp32:esp32:esp32s3:FlashSize=8M,PSRAM=enabled,CDCOnBoot=cdc` |
| 5 | 用原生 USB 口（`VID_303A:1001`）烧录 | `Hash of data verified` / `UPLOAD_EXIT=0` |
| 6 | 串口 115200 看启动横幅 | 出现 `v1.5.0`、`ai-status/1`、`[HTTP] Web服务器已启动` |
| 7 | 浏览器打开设备 IP 或 `http://esp32s3-ai.local/` | 看到 Web 面板与「来源与绑定」卡片 |
| 8 | `GET /api/hello` | `proto == "ai-status/1"`、`fw == "1.5.0"` |

编译/烧录更详细的环境说明见 `docs/03-ESP32端固件与接口.md`。

## 6. 部署后验收清单

```
□ python main.py selftest                 → 67 项通过
□ python main.py identity                 → 有本机的 source_id
□ python main.py hooks-config             → 命令里的路径指向本机的 main.py
□ 重启 CodeBuddy 会话后发一句需求          → /health 的 event_count 增长

□ python main.py probe                    → 串口命中或 /api/hello 命中
□ 设备 GET /api/status                    → msg 以 [来源ID] 开头
□ python main.py demo                     → 7 种灯效依次变化，回执 ok=true
□ 服务停止 16 秒                          → 设备自动转 offline（粘性状态除外）
□ 若启用「仅绑定来源」                     → 未绑定电脑日志提示 source_not_bound
```

## 7. 排错速查

| 症状 | 最可能原因 | 处理 |
| --- | --- | --- |
| 灯一直暗蓝不动、`event_count = 0` | Hooks 没装或没重启会话 | `install-hooks --write` → 重启/新建会话 → CLI 用户 `/hooks` 审核 |
| `health` 连不上 | 服务没启动 / 端口被改 | 跑 `start.bat`；确认 `listen_port` |
| `probe` 找不到串口 | 线没插、被别的进程占用、板子没上电 | 设备管理器看 COM；关掉占用程序；重插 USB |
| 串口打开后板子重启 | DTR/RTS 被置位 | PC 端已强制置 false；检查是否有其它串口工具同时打开 |
| HTTP 全超时 | PC 与设备不同网段 | 回同网段 / 连设备 AP / 改用 USB 串口 |
| `ack ok=false / invalid_seq` | 设备内部转移自增了 seq | PC 端会自动重同步并补发一次，无需处理 |
| `source_not_bound` | 设备处于「仅绑定来源」且本机未被勾选 | 在设备网页勾选本机 ID，或切「全部接受」 |
| `lower_priority` | 设备正停在更高优先级的粘性状态 | 先处理该状态或 `python main.py clear` |
| `disabled` | 状态引擎被关 | 设备网页打开「AI 状态灯」 |
| 中文 `msg` 变 `???` | PowerShell 请求编码问题 | 用 UTF-8 字节 + `Content-Type: application/json; charset=utf-8` |
| UDP 4210 收不到广播 | Windows 防火墙拦截入站 | 用 mDNS；或管理员放行 UDP 4210 入站 |
| `start.bat` 一闪而过 | Python 不在 PATH | 把 `python` 改成解释器绝对路径，或重新安装并勾选 Add to PATH |
| 需要人处理时灯不变化 | 还在跑旧版服务进程 | 关掉旧窗口重新 `start.bat`；`GET /health` 的 `version` 应为 `1.2.0` |
| 等待态灯一直不解除 | IDE 既没发 `UserPromptSubmit` 也没发 `PostToolUse` | `python main.py clear` 手动释放；或发一句新需求 |
| 长时间命令被误判为等待确认 | 推断阈值偏小 | `config.json` 把 `need_confirm_after_ms` 调到 `8000`~`15000` |

## 8. 从旧版本升级

| 从 | 到 | 要做 |
