# 03 · ESP32-S3 端固件与接口（v1.5.0 修复版）

## 一、硬件与引脚

| 项 | 值 |
| --- | --- |
| 主控 | ESP32-S3-N8R2（8MB Flash / 2MB QSPI PSRAM，双核 240MHz） |
| 状态灯 | 板载 WS2812，GPIO48（部分板在 GPIO38），**只有 1 颗** |
| 原生 USB | `VID_303A:1001`，Windows 常见 COM16（CDC `MI_00` / JTAG `MI_02`） |
| USB 转串口 | CH343 `VID_1A86:55D3`，常见 COM17，接 UART0（GPIO43 TX / GPIO44 RX） |
| 串口参数 | 115200 8N1；PC 打开时 DTR/RTS 必须置 false，否则可能触发复位 |
| 其它 | GPIO1~6 电容触摸、GPIO38 DOUT、GPIO39 PWM、GPIO11 DIN、GPIO10 ADC |

全部 GPIO 为 3.3V 逻辑、非 5V 容忍；GPIO26~32 通常被 Flash/PSRAM 占用。供电建议 5V / ≥500mA。

## 二、编译与烧录

| 项 | 值 |
| --- | --- |
| 框架 | Arduino-ESP32 Core 3.2.1（底层 ESP-IDF 5.x） |
| FQBN 参考 | `esp32:esp32:esp32s3:FlashSize=8M,PSRAM=enabled,PartitionScheme=default_8MB,CDCOnBoot=cdc` |
| sketch 目录 | 目录名必须等于主文件名：`ESP-S3-Demo1/ESP-S3-Demo1.ino` |
| 烧录口 | 优先原生 USB CDC（COM16） |
| 成功标志 | `Hash of data verified` / `UPLOAD_EXIT=0` |

首次使用**必须先改 WiFi 占位符**，见 `esp32/README.md` 与 `docs/01` 第 3.2 节。ESP32-S3 只支持 2.4GHz。

烧录后串口 115200 应看到 `v1.5.0`、`ai-status/1`、`[HTTP] Web服务器已启动`；无 `assert failed` / `Backtrace` / 反复重启。

## 三、网络与设备发现

连接优先级：`NVS 自定义网络 → 默认主网络 → 备用网络 → AP 兜底`。候选全部失败约 30 秒后开启 AP。

| 机制 | 说明 |
| --- | --- |
| STA | 连上 WiFi 后由 DHCP 分配 IP（会变） |
| AP 兜底 | `ESP32S3-Fallback` / 你设置的 `AP_PASSWORD`，固定 `192.168.4.1` |
| mDNS | `esp32s3-ai.local`（推荐主通道，已实测解析 + ping 通过） |
| UDP 广播 | 启动快发 3 次、之后每 30 秒，双发 `255.255.255.255:4210` 与子网定向广播；载荷 `t=esp32s3_hello` |
| `GET /api/hello` | 设备能力协商，PC 端校验 `proto == ai-status/1` |
| `GET /api/discover?peer=<PC IP>` | 立即触发一次发现广播，返回 `beaconCount/Ok/Fail/lastErrno/broadcastIP` |

> **跨网段无解**：广播、mDNS、/24 扫描都过不了路由器。PC 与设备必须同网段，或连接设备 AP，或改用 USB 串口直连。
> **Windows 防火墙**：默认拦截外部主机发往 UDP 4210 的入站包，需管理员执行 `New-NetFirewallRule -DisplayName "ESP32 AI Status Discovery (UDP 4210 In)" -Direction Inbound -Protocol UDP -LocalPort 4210 -Action Allow`；不改防火墙时直接用 mDNS 即可。

## 四、HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 内置 Web 调试面板（PROGMEM） |
| GET | `/api/system` | 系统信息（展示字段 + 机器可读字段） |
| GET | `/api/hello` | 设备发现与能力协商：`proto` / `fw` / `cap` / `bindMode` / `mdns` / `udpPort` / `sourceField` / UDP 诊断计数 |
| GET | `/api/status` | 当前状态快照：`state` / `seq` / `prio` / `sticky` / `link` / `msg` / `engine` / `brightness` / `src` / `bindMode` / `sourceCount` |
| POST | `/api/status` | 设置状态（必须带 `Content-Type: application/json`） |
| OPTIONS | `/api/status` | CORS 预检，返回 204 |
| GET | `/api/sources`、`/api/bind` | 来源与绑定清单（v1.5.0） |
| POST | `/api/bind` | `{"src":"PC-A","on":1,"mode":1,"clear":0}` 设置白名单/模式 |
| GET | `/api/discover` | 主动触发一次发现广播 |

CORS：`Access-Control-Allow-Origin: *`、`Allow-Methods: GET,POST,OPTIONS`、`Allow-Headers: Content-Type`。**无鉴权、无 TLS**，仅限可信局域网。

## 五、WebSocket 命令

`ws://<ip>/ws`，只处理完整单帧文本，1~4096 字节。请求 `{"cmd":"...","val":...,"reqId":"..."}`，响应 `{"type":"...","data":...}`。

| 分类 | 命令 |
| --- | --- |
| 系统 | `init`、`sys_info`、`sys_restart` |
| WiFi | `wifi_scan`、`wifi_retry`、`wifi_save`、`wifi_clear` |
| LED（手动） | `led_color`（8bit HSV）、`led_toggle`、`led_rainbow`、`led_breathe`、`led_effect` |
| GPIO | `gpio_out`、`gpio_pwm`、`gpio_pwm_freq`、`gpio_read`、`gpio_scan` |
| 触摸 | `touch_read` |
| 双串口 | `usb_send`、`usb_baud`、`usb_config`、`usb_echo`、`usb_info` |
| AI 推理演示 | `ai_infer`（随机权重，无语义） |
| AI 状态灯 v1.4 | `status_set`、`status_heartbeat`、`status_clear`、`status_get`、`status_enable` |
| 亮度 v1.4.1 | `status_brightness`（0~255，NVS 持久化） |
| 来源与绑定 v1.5 | `sources_get`、`status_bind`、`bind_mode`、`bind_clear` |

推送类型：`system` / `touch` / `gpio` / `wifi_scan` / `usb_recv` / `ai_result` / `status`（广播）/ `status_ack`（单播）/ `sources`（v1.5，每 3 秒及每次变更）。

> 状态引擎激活时接管 WS2812，`led_*` 命令仍回执但不改变实际灯色（提示 `status_engine_active`）；`status_clear` 释放接管。

## 六、串口 JSON Lines

一行一个 JSON、以 `\n` 结尾、≤512 字节、UTF-8。

PC → 设备：

```json
{"t":"status","v":1,"src":"PC-A","state":"thinking","seq":42,"ttl":15000,"msg":"[PC-A] 正在分析需求"}
{"t":"heartbeat","v":1,"src":"PC-A","state":"thinking","seq":43}
{"t":"ping","v":1,"src":"PC-A"}
{"t":"clear","v":1,"src":"PC-A"}
{"t":"get","v":1,"src":"PC-A"}
{"t":"sources","v":1}
{"t":"bind","v":1,"src":"PC-A","on":1}
{"t":"bind_mode","v":1,"val":1}
```

设备 → PC：

```json
{"t":"pong","v":1,"fw":"1.5.0","proto":"ai-status/1","mac":"...","ip":"...","bindMode":0,"mdns":"esp32s3-ai.local"}
{"t":"ack","v":1,"ok":true,"seq":42,"state":"thinking"}
{"t":"status","v":1,"state":"thinking","seq":42,"prio":20,"sticky":false,"link":true,"msg":"..."}
{"t":"state","v":1,"state":"offline","reason":"timeout"}
{"t":"sources","v":1,"data":{...}}
```

以 `{` 开头且能解析出 `t` 的行视为协议帧，处理后不再广播到网页终端；其余行仍按串口桥接上送 `usb_recv`。

## 七、来源与绑定（v1.5.0 核心）

| 项 | 说明 |
| --- | --- |
| `src` | 可选来源 ID，≤40 字节；逗号与控制字符规范为 `_`；不带的旧客户端视为匿名来源 `*` |
| `bindMode = 0` | **全部接受**（默认，等同 v1.4.1），所有来源参与聚合 |
| `bindMode = 1` | **仅绑定来源**：只有白名单里的 `src` 参与灯效聚合 |
| 白名单 | 最多 8 条，可多选、可清空，NVS `status_cfg/bind_mode` + `status_cfg/bind_srcs` 持久化，开机恢复 |
| 每来源独立 | 状态、`seq`、优先级、TTL、粘性、15s 超时全部按 `src` 单独计时，互不覆盖 |
| 槽位 | 最多 8 个来源，满时淘汰最久未更新者 |
| 未绑定 | 仍记录并显示（方便事后勾选），但不参与聚合；状态帧回 `ok=false / reason=source_not_bound` |
| 单灯聚合 | 取所有「已绑定且在线」来源中优先级最高的状态；同级取最近变化者 |

网页「来源与绑定」卡片：模式徽标、四个按钮（全部接受 / 仅绑定来源 / 清空绑定 / 刷新）、每个来源一行（勾选框、ID、状态、心跳距今、`msg` 摘要、在线/离线）。「AI 状态灯」卡片的状态信息里会显示 `src=<当前驱动来源>`。

`/api/sources` 与 `type=sources` 的 `data` 结构：

```json
{
  "mode": 1, "boundCount": 2, "sourceCount": 3, "sourceField": "src",
  "binds": ["PC-A", "PC-B"],
  "sources": [
    {"src":"PC-A","state":"thinking","seq":42,"msg":"...","age_ms":1200,"online":true,"bound":true,"sticky":false}
  ]
}
```

## 八、错误码

| `reason` | 含义 | PC 端建议 |
| --- | --- | --- |
| `invalid_json` / `payload_too_large` | 帧格式或长度问题 | 缩短 `msg`、检查换行 |
| `invalid_state` | 未知状态名 | 检查枚举与固件版本 |
| `invalid_seq` | seq 回退/重复 | PC 端自动重同步并补发 |
| `lower_priority` | 被更高优先级状态挡住 | 不重试，先处理高优先级状态 |
| `disabled` | 状态引擎关闭 | 网页打开「AI 状态灯」 |
| `source_not_bound` | 本机未被绑定（v1.5） | 去网页勾选，或切「全部接受」 |
| `too_many_sources` / `invalid_src` | 来源槽满 / ID 非法 | 减少来源或规范 ID |

## 九、关键时序

| 事件 | 值 |
| --- | --- |
| WS 客户端注册 | 连接后等 500~700ms 再触发广播事件 |
| 状态心跳 | 5000ms（PC 端必须实现） |
| 心跳超时转 `offline` | 15000ms（粘性来源除外） |
| `done` 自动回 `idle` | 5000ms |
| 灯效刷新 | 30ms |
| 串口无换行上送 | 静默 40ms |
| LED/来源列表推送合帧 | 500ms（避免 WS 队列洪泛） |

## 十、验收清单

```
□ GET /api/hello                  → proto=ai-status/1, fw=1.5.0, cap 含 sources/bind/mdns
□ 串口 {"t":"ping","v":1}         → pong，且网页终端不出现该帧
□ POST /api/status thinking       → ok=true，紫色慢呼吸
□ 连续 5s 心跳                    → 状态保持
□ 停上报 16s                      → state=offline，极暗蓝
□ POST need_confirm               → 橙色快闪；停心跳 16s 仍不消失
□ POST thinking（无 force）        → lower_priority
□ /api/sources                    → 能看到各 PC 的 src 与在线状态
□ bindMode=1 且只绑 PC-A          → PC-B 状态帧回 source_not_bound
□ 网页「来源与绑定」勾选           → 立即生效，重启后仍在（NVS）
□ status_clear                    → 回 idle，LED 交还手动控制
```

## 十一、已知限制

- 只有 1 颗灯，多来源只能聚合显示一个状态。
- 设备不做状态历史，只有「一个当前态」；统计需 PC 端落库。
- 无鉴权、无 TLS、开放 CORS；WiFi 密码明文存 NVS 且经 WS 明文传输。
- 跨网段发现不可行；UDP 4210 在 PC 侧需管理员放行防火墙。
